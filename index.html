Built for the changes that actually stop things working

Every rule is backed by a documented Salesforce platform change with a source link. No generic code-quality scores, no health-check noise — only what has a date attached.

Authentication retirements

Integrations still logging in with flows Salesforce is switching off, such as the OAuth username-password flow and SOAP API login(), grouped by app and user.

API version retirements

Traffic on API versions that are being retired, and components that have fallen far behind the current release.

Hardcoded instance URLs

Instanced hostnames in Apex, Visualforce, Named Credentials, CSP Trusted Sites and Remote Site Settings that stop resolving when Salesforce enforces My Domain URLs.

Retired automation

Active Process Builder processes and Workflow Rules that keep running without support or bug fixes, ready for migration to Flow.

How it works

  1. Install from AppExchange

    A managed package installed into your org. Assign the ReleaseGuard permission set to the people who run scans.

  2. Run a scan

    The scan runs in the background inside your org and reads only configuration and usage data the rules need.

  3. Work the findings

    Each finding names the component, shows the evidence and the enforcement date, and links to the official Salesforce documentation.

  4. Re-scan every release

    New rules arrive with package updates. Fixed issues close automatically when the rule checked them successfully.

Honest results

A tool that says "passed" when it could not look is worse than no tool. Every rule ends in one of five clear outcomes:

  • Has findings
  • Passed
  • No evidence in the period
  • Not evaluated — with the reason
  • Error

Rules based on activity, such as login history, report "no evidence in the last N days" rather than "passed", because a quiet month is not proof.

Your data stays in your org

  • Runs entirely inside your Salesforce org — no external servers, no data sent to us.
  • The only callout is to your own org's Tooling API, built from your org's domain at runtime, and it is optional.
  • Least privilege: access through a permission set, checked on the server.
  • No IP addresses and no source code snippets are stored as evidence.
  • Built for AppExchange Security Review.
